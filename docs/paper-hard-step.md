# 论文硬步模式（paper_grounded）

2026-10-26用户口径：题面不能为了“好验证、好自足”而降低难度。论文能推出来的结论在理论上就成立；只需保留论文最难的那一步给解题者，其余以论文推导为正确性依据。配置为[library-paper-hard-step.toml](../configs/library-paper-hard-step.toml)，即来源启发配置加`correctness_basis = "paper_grounded"`。旧配置默认`self_verified`，历史run与已测成绩不追溯改判。

## 为什么改

library30的53道首4次全对题审计（[easy53](validation/easy53-audit-2026-10-25.md)）显示：46道的“最难一步”只是常规计算或标准引理，5道把关键结构写进了题面前提，物理11道中10道被特化成孤立的线性/二次代数。当时的流程有三股压力把题压简单：

1. 题面自足要求让作者倾向把论文的关键结构写成定义；
2. 受限有理算术反代只能覆盖初等表达式，倒逼特化；
3. 盲推导或挖空审查的“推不出/不确定”被当作拦截理由。

此后的6Luna深度门禁（difficulty10、shortcut10）又走向另一端：绝大多数提案在锁定前被判too_easy。本模式不再用6Luna判断难度，难度只由GLM实测决定。

## 门禁口径

| 检查 | self_verified（原口径） | paper_grounded |
|---|---|---|
| 正确性审查（consistency_review） | fail或uncertain阻断 | 只有fail阻断；uncertain记录 |
| 程序反代 | 未覆盖、证书未忠实翻译均阻断 | 未覆盖只记录；忠实翻译下的真实反例仍阻断，任一历史尝试出现过也阻断 |
| 题面审查（audit） | 七项全过 | 只看科学项；`no_shortcut`、`substantive_delta`只记录 |
| 挖空审查 | 五项全pass | `hidden`、`not_answer_only`必须pass；`recoverable`只有给出具体缺失前提或多解见证（fail）才阻断；选择依据与必要性只记录 |
| 蓝图审查 | 独立逐步复核完整推导，深度意见也阻断 | 仅核引用与适用条件；不重证论文、补论文省略的代数或评深度，改写引入的具体错误仍阻断 |
| verifier对抗、HLE判分、4→16规则 | 不变 | 不变 |

口径记录在候选的`correctness_basis`上，采样、导出与报告入口都按候选自身口径复核；口径与运行配置不一致时要求新版本，不能借新口径放行旧候选。本模式不能与6Luna难度对抗同时启用。

## 提示词

2026-10-27起，新配置先调用`ScientificGoalSelection`，只返回科学目标、原始前提、必要推理挑战和高难案例对照，不返回答案或题面。随后`ResultSelection`保留该目标，确定自然答案形式和金标，再生成完整参考解、审查及题面。选题、完整推导和题面提示均取消短答案与必须定量的偏好；定性结果、完整分类、构造、算法和证明可以作为科学目标。不能为了获得一个易比较的系数而缩小目标，也不能把一条短计算拆成冗长输出清单来冒充难度。

参考来自[FrontierMath公开案例及解答](https://epoch.ai/frontiermath/tiers-1-4/benchmark-problems)，配置为`configs/scientific-goal-references.json`。目前包含BMO极值和Tsirelson组合结构两例的原创简要结构总结及来源链接，不复制题目全文或金标。它们的Tier 4/3是来源标签，尚未按本项目GLM5.2协议校准；物理选题可参考结构发现、全局义务或构造/排除的联系，不要求复刻数学对象或定量输出。

目标选择收据随`KnownResult.scientific_goal`保存，包含来源哈希、参考案例哈希、实际模型、请求、提示和模型配置。目标或原始前提被换掉、收据缺失、来源/参考案例/协议改变时，通用采样与导出均拒绝复用；规划清单及运行指纹也绑定案例内容。历史种子必须在新run重新选择目标，不能导入旧通过资格。

`grading_requirement`区分最终答案等价比对与论证/见证验证。长答案、定性结论可沿用前者；完整证明、非唯一构造或算法若需要验证论证/见证，应标记`argument_or_witness_validation`。这类目标允许选择和保留，但当前采样返回`evaluation_contract_uncovered`，不购买GLM/judge、不导出为通过题，等待独立支持的评测合同。当前官方HLE提示、判分模型和4→16规则未改；本改动没有实现或宣称形式化证明验收。

蓝图审查（`review_blueprint` / `blueprint_review`）直接使用独立的短提示`prompts/hardstep_blueprint_audit.txt`，不再拼接要求“advisory模式下独立重证”的旧提示。请求显式带`correctness_basis=paper_grounded`与`review_scope=paper_reference_and_premises`。其余七个阶段继续在原提示后追加`prompts/hardstep_<阶段>.txt`条款；全部提示进入哈希与运行指纹。要点为：

- 先选论文机制启发的科学目标，再选择自然答案形式；可用原结果或明确标注的改编，保留目标所需推理，不以答案长度或是否定量筛选；
- 参考证明可按论文推导引用（页码、公式、定理编号），逐项核对其前提在本实例成立；
- 题面只给论文出发时的原始对象、定义、模型规律、数据与输出约定；隐藏关键推理及一切会泄露它的脚手架（辅助定义、ansatz、有效量、命名定理、可直接套用的恒等式），不为保险而加提示；
- 审查只在给出具体见证时判缺信息或错误；“难推”“解题者可能想不到”不算缺信息。

蓝图阶段的通过标志只表示引用与适用条件核对未发现具体错误，不代表独立证明整篇论文。引用忠实、前提满足时，论文省略了代数展开或审查模型无法重建证明，只记`reason/source_notes`，不触发作者重写。针对一般模型的反对意见必须先核对本实例的完整前提和处方；不能直接作为金标反例。题面自洽、改题产生的矛盾、反代中的真实反例与verifier仍按现有流程检查。本次修改不更新在途快照、不重判已有拒绝；新提示只能进入新run。

本次精简的[真实轨迹回放](validation/paper-reference-review-2026-10-26.md)包括两个原蓝图通过与一个条件矛盾对照拒绝；个人VM真实PG431项测试通过。该组件验证不代表完整科学审查或GLM难度通过。

## 边界

放宽的是“未能核实”的处理，不是正确性标准：真实反例、矛盾、误用论文结论、两种合法读法答案不同等具体缺陷仍阻断。uncertain通过的题可能包含审查未发现的错误，由verifier对抗、HLE判分与0/16后的错题排查兜底。后置科学复核使用与前置相同的`correctness_basis`，继续检查真实答卷、判分歧义及具体错误；verifier对抗仍要求所有对照取得明确结论，未知或HLE争议阻断，不将前置的uncertain记录规则扩展到该阶段。实测结果见验证记录。

2026-10-27提示词一致性核查还统一了以下边界：`LockedProofDraft`只输出推导与设计，锁定金标、目标及原始前提由程序绑定；修复反馈不得要求改写金标。题面生成、初审、改题重审及后审均收到锁定目标、评测义务与正确性口径。证明目标可陈述待证命题，但不得泄露论证；结论目标不得靠追加证明义务强行变难。隐藏的是可恢复的辅助推理，独立模型前提仍须保留；改编构造使用自身锁定模型的原始条件，不能机械退回论文原模型。已锁定目标的深度意见只记录；推导修复夹带`target_depth`意见时，不得跳过具体错误修复或恢复主观深度否决。精确算术提示统一为整数幂−16至16及六种比较关系，与执行器一致。
