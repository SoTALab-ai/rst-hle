# 论文硬步模式（paper_grounded）

2026-10-26用户口径：题面不能为了“好验证、好自足”而降低难度。论文能推出来的结论在理论上就成立；只需保留论文最难的那一步给解题者，其余以论文推导为正确性依据。配置为[library-paper-hard-step.toml](../configs/library-paper-hard-step.toml)，即来源启发配置加`correctness_basis = "paper_grounded"`。旧配置默认`self_verified`，历史run与已测成绩不追溯改判。

## 为什么改

library30的53道首4次全对题审计（[easy53](validation/easy53-audit-2026-10-25.md)）显示：46道的“最难一步”只是常规计算或标准引理，5道把关键结构写进了题面前提，物理11道中10道被特化成孤立的线性/二次代数。当时的流程有三股压力把题压简单：

1. 题面自足要求让作者倾向把论文的关键结构写成定义；
2. 受限有理算术反代只能覆盖初等表达式，倒逼特化；
3. 盲推导或挖空审查的“推不出/不确定”被当作拦截理由。

此后的6Luna深度门禁（difficulty10、shortcut10）又走向另一端：绝大多数提案在锁定前被判too_easy。本模式不再用6Luna判断难度，难度只由GLM实测决定。

## 门禁口径

| 检查 | self_verified（原口径） | paper_grounded |
|---|---|---|
| 正确性审查（consistency_review） | fail或uncertain阻断 | 只有fail阻断；uncertain记录 |
| 程序反代 | 未覆盖、证书未忠实翻译均阻断 | 未覆盖只记录；忠实翻译下的真实反例仍阻断，任一历史尝试出现过也阻断 |
| 题面审查（audit） | 七项全过 | 只看科学项；`no_shortcut`、`substantive_delta`只记录 |
| 挖空审查 | 五项全pass | `hidden`、`not_answer_only`必须pass；`recoverable`只有给出具体缺失前提或多解见证（fail）才阻断；选择依据与必要性只记录 |
| 蓝图审查 | 深度意见（target_depth）阻断 | 深度意见只记录；推导、答案与前提缺陷照常阻断 |
| verifier对抗、HLE判分、4→16规则 | 不变 | 不变 |

口径记录在候选的`correctness_basis`上，采样、导出与报告入口都按候选自身口径复核；口径与运行配置不一致时要求新版本，不能借新口径放行旧候选。本模式不能与6Luna难度对抗同时启用。

## 提示词

只在原提示词后追加`prompts/hardstep_<阶段>.txt`条款，原文件不变，条款进入全部提示哈希与运行指纹。覆盖结果选择、完整推导、蓝图审查、题面生成、题面审查、挖空审查、盲推导和正确性审查八个阶段，要点为：

- 目标选论文自身关键推理（论文的主要新思路）支撑的短答案结果；可直接用论文结果，也可特化，但特化后该推理仍须不可绕过，优先一般参数、精确常数、阈值或完整分类；
- 参考证明可按论文推导引用（页码、公式、定理编号），逐项核对其前提在本实例成立；
- 题面只给论文出发时的原始对象、定义、模型规律、数据与输出约定；隐藏关键推理及一切会泄露它的脚手架（辅助定义、ansatz、有效量、命名定理、可直接套用的恒等式），不为保险而加提示；
- 审查只在给出具体见证时判缺信息或错误；“难推”“解题者可能想不到”不算缺信息。

## 边界

放宽的是“未能核实”的处理，不是正确性标准：真实反例、矛盾、误用论文结论、两种合法读法答案不同等具体缺陷仍阻断。uncertain通过的题可能包含审查未发现的错误，由verifier对抗、HLE判分与0/16后的错题排查兜底；后置复核仍不放宽。实测结果见验证记录。
