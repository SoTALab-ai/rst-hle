# RST 是否适合这条题目生产线

结论：适合借用“解答先行、题面/验证对齐、验证后递归”的工程骨架；跨到 HLE 风格学科题仍需实验。当前优先实现可复核质检，再决定怎样扩展生成器。

所指论文为 [Recursive Synthesis for Long-Horizon Terminal Tasks, arXiv:2608.05466v3](https://arxiv.org/html/2608.05466v3)。论文报告在终端任务上多轮合成、验证和下游训练有效；这里引用的是作者报告，并非我们的独立复现。37,484 道、约 $0.05/题和 15 轮稳定性属于其终端任务设置，不能直接作为学科题生产预算或成功率。

可迁移的因果链：先从来源和可靠推导建立参考解，再写充分定义的题面与判分契约；只有质量验证通过的版本才进入种子池；保存血缘、失败原因、修复次数，控制单一来源和操作符占比。难度指标使用独立 solver 的实测表现，不使用题长或推导字数代替难度。

主要差异是验证器。RST 可以在新沙箱执行参考解；HLE 题常涉及文献事实、抽象证明或专家知识，参考解和 judge 同意仍可能共同出错。因此本项目先做证据存在性、题面完整性、分离调用复核与盲答判分，不宣称具有通用学科证明器。后续应为棋类接规则引擎、数学接可计算/形式化证书、数值题接可重算 oracle；知识题核对原始资料与适用版本。

需要避免两个误用：增加步骤不一定增加有效推理；0/16 也可能来自错题或缺材料。先检查正确性与唯一性，再看采样窗口。16 次样本的窗口是采购规则，并不精确估计真实成功概率。原始 HLE Diamond 是经过清理的评测子集，本项目生成的是 HLE 风格候选题，不是官方 Diamond 的新增题。[官方数据说明](https://huggingface.co/datasets/cais/hle-diamond/blob/main/README.md)

数据覆盖同样限制递归。需求中 Other 743 + Humanities/SS 490 = 1,233 道，占 61.65%。仅 arXiv 无法保证覆盖音乐、影视、舞蹈、棋类等，需要预备一手文本资料、规则版本和必要的谱面转写。当前自动采集实现 arXiv；自备材料库入口承担其他来源。

建议验证采用同预算四组：一次生成；只重写题面的递归；解答先行递归；解答先行加证据/独立质检递归。在相同来源池、子类比例、模型与推理预算下比较，每轮随机抽样独立核查。核心指标为“去重后的正确且合格独立题数/费用”、每子类留存率、错误金标率、歧义率、重复率、每谱系有效增量及 solver 正确次数分布。报告所有失败，不只展示通过样例。

初始试验应是多子类小批次，先跑 CS/AI、数学/算法和一个知识型类别，确认 QC 稳定后再扩到长尾。停止条件应包括错误金标增加、重复率升高和独立合格收益不再增长，而不是预设“递归轮数越多越好”。上述是本项目的试验建议，尚未得到试验结果支持。
