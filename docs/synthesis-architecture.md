# 合成架构与模块归属

## 依赖方向

```mermaid
flowchart LR
    A[期刊DOI队列与开放仓储] --> M[元数据规范化 / DOI去重登记]
    M --> B[下载原PDF和补充材料 / 哈希去重]
    B --> C[论文库: 6Luna逐页读取一次]
    C --> D[PG版本与页索引 / 内容寻址原件和转录]
    D --> K[50份完整独立材料 / 每篇规划1–5题]
    K --> E[定位来源已有结果]
    E --> F[锁定答案、完整推导、逐步审查]
    F --> G[隐藏最难步骤并生成题面]
    G --> H[独立解答、自洽反代、verifier对抗]
    H --> I[GLM首4次 / 必要时16次]
    I --> J[降难或拒绝 / 后置复核去重]
```

材料库与出题批次独立。读取全文不购买GLM答卷，不生成题目，不自动向`sources`写入“已通过”来源。下游定位与科学审查仍需冻结具体论文版本、文档、物理页与转录版本。

## 当前代码归属

| 模块 | 职责 |
|---|---|
| `discovery.py`、`open_access.py`、`paper_metadata.py` | DOI/期刊依据、元数据身份与观察版本、下载前去重、开放位置；不宣称全文或理论适用性已通过 |
| `paper_acquisition.py`、`pdf_library.py` | 冻结候选队列、下载原件、研究类型筛选、正文/补充分存 |
| `paper_ingest.py` | 严格入库清单、直接模型转录、页码覆盖、PG论文/文档/解析/页面索引、显式导出 |
| `pdf_review.py`、`pdf_precision.py`、`pdf_ocr.py` | 旧冻结批次的MinerU与独立图像复核；新直接读取入口不调用旧逐页验收 |
| `artifacts.py`、`postgres.py`、`sql/` | 对象完整性、短事务、显式迁移、写锁、请求收据和预算 |
| `experiment.py`、`pipeline.py`及出题/质检模块 | 来源结果锁定、推导修复、题面、科学审查、难度评测与谱系 |
| `library_questions.py` | 50份完整材料冻结、不同推理结构规划、来源锚点及选页核对、原出题管线分片试产 |
| `llm.py`、`costs.py`、`campaign_costs.py` | 实际模型校验、原始请求/响应、逐HTTP尝试、缓存、失败/未知/在途与跨阶段实际用量核算 |
| `easy_audit.py`、`scripts/audit_easy_cohort.py` | 只读核对首4/4候选、既有答卷/判分/盲解封印与人工逐项判断，导出脱敏账本；不调用模型、不写回原run |
| `difficulty_adversary.py` | 新首题锁定前的完整构造对抗、实际题面后的盲解路线挑战、有限增强修订与PG/CAS检查点；不改已测题和verifier冻结题 |

## 材料阶段合同

原PDF是来源依据；模型转录是可检索、可重复使用的派生文本。程序核对哈希、JSON结构、物理页范围及完整覆盖，模型应明确报告未读清的位置。它们不证明公式语义正确，也不能发现所有被模型误抄却自称读清的符号。

不追加第二个模型逐页重读全文。出题时继续执行独立科学审查；出现具体来源疑点时只回看关联原页。图、图注不进入转录范围，正文、公式、数学表格和脚注保留。材料存在缺页/未读清时，严格全文导出会失败；补充材料状态仍独立记录，不由转录完成推断齐全。

## 当前边界

已实现单进程内部并发、PG单写者互斥和已付费回答复用；没有宣称接通多worker分布式服务或管理API。旧`sources`/arXiv目录与新`library_*`表分开，不伪造arXiv ID迁就旧schema。论文库导出用于结果定位，不能绕过现有正确性门禁。

批次实测数字见[验证索引](validation/README.md)，命令见[验证方法](local-validation.md)。
