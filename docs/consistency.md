# 难度评测前的独立自洽审查

首次20条理论谱系的 P03B 第一轮改写虽然完成7/16，但后置复核发现：金标允许的复耦合域违反无吸收模型的能量守恒，且给出的暗态不满足题面定义的 `Bd=0`。这是生成版本和金标的质量缺陷，原首轮综合复核漏检；该7/16不能认证有效难度。历史题面、金标、采样与判分保留，新增检查不覆盖原记录。

新顺序：生成参考解和题面 → 结构/证据/综合复核 → **独立盲推导 → 自洽审查** → 首4次盲答 → 必要时补到16次 → 错答争议复核/去重 → 保留或难度演化。前置正确性检查不依赖通过率，必须在首4次之前完成。

## 三个分开的调用

`[consistency]` 默认使用 `gpt-6-luna high`，可以独立配置模型和网关。它与 HLE 的 `[judge]` 分开计费和存档，后者继续使用官方答案匹配模板、`gpt-6-luna medium`，不修改官方判分口径。

1. `consistency_solve` 只提供字面题面，不提供金标、作者推导、rationale、父题、综合审查结论或GLM作答。独立推导所有输出、识别矛盾或缺失条件。
2. `consistency_review` 提供题面、作者金标与推导、第一步独立推导及截取来源；分别检查前提、定义、参数域、参考答案和物理条件。必须写出具体代入、恒等式、推导或缺失条件，物理模型要检查守恒/精确矩阵关系。数值反例可以证伪，单个通过例不能证明全域成立。
3. `consistency_certificate` 仅看原题、原金标、要求输出和验算方案，不看前一审查结论或通过率；逐个核对公式翻译，修复验算表达式但不能修复原金标。只有确认忠实翻译的证书才交程序执行。实际小样本曾出现把N=1+|κ|²错译为1+norm2([1,κ])，需要这层拦截，不能把错译产生的残差算作科学反例。

每项结论为 `pass`、`fail` 或 `uncertain`；只有纯数学题的物理条件可填 `not_applicable`。四个核心检查不能跳过。任何失败或未消除的不确定都阻止采样；独立推导与金标意见不同时，要论证哪一个正确，不能按一致率或金标权威投票。第一次独立推导的不确定可以在第二次审查中明确解决；第二次仍不确定则不能通过。

这是模型审查，不是可执行的通用证明器。三个请求使用独立上下文，但默认是同一模型，仍可能有相关错误。来源仍受配置的文本长度上限影响；后置争议复核继续保留，人工学科复核仍有价值。100条新理论实验还启用题面生成之前的参考蓝图审查，见[出题设计](question-design.md)。

## 答案反代：由程序执行精确算术

这一步在verifier之前。验算失败要区分：证书翻译/定位错误只修证书；受限表达式不支持属于覆盖未完成；忠实翻译下违反原式才是上游缺陷证据。题面/推导的修复应在进入verifier前完成并重审受影响检查。若锁定golden本身错误，当前构造退回，不能原地更换答案。进入verifier后的晚发现缺陷只能拒绝并返回上游，不能从该阶段改题。

标量整次幂的执行范围现为−16至16，AST、整数位数及矩阵尺寸上限保持。此修改覆盖论文旧证书中的9、10、11次幂；有限点通过仍不是全域证明，也不能覆盖分布、π或未支持的根式。

### 失败归因与定向修复

`Candidate.preflight_repair`记录结构化类别、责任阶段、失败检查、未覆盖输出和修复指令；按以下优先级处理，不从自然语言错误消息猜测科学结论：

| 类别 | 责任阶段与动作 |
|---|---|
| `scientific_review` | 自洽审查的前提、定义、域、证明或答案失败/不确定；反馈作者定位步骤，重做前置审查，无法修复则拒绝 |
| `certificate_translation` | 未确认忠实翻译；只修验算证书，不认定金标被证伪 |
| `gold_counterexample` | 忠实翻译且合法反代点违反原式；返回上游检查推导/题面，禁止把失败约束改成通过。锁定golden错误则拒绝当前构造 |
| `certificate_execution` | 受限表达式不支持、检查点无效或输出未覆盖；只修证书的表达式、合法点、定位和覆盖，不能删原约束 |

`certificate_max_repairs`默认0，保留历史配置；新`library-source-inspired.toml`为1，最多初次加一次定向证书修复。模型仅收到固定原题、golden、要求输出、原验算方案及结构化执行反馈，不得修改题面、答案、目标或完整推导。每轮使用不同请求盐，保存`certificate_attempts`的完整证书、反代结果、实际模型与收据；最终证书须与末次记录一致，早先忠实翻译的真实反例不能被后续通过覆盖。协议绑定修复提示与次数，变更后不复用旧证书通过资格。

证书修复用尽直接拒绝并保留“验证未覆盖/未确认”的原因，不进入外层整题重写，也不算难度失败。只有真实科学缺陷返回作者修复预算；锁定结果不变，修复用尽或结果本身为假则拒绝。接口/schema失败仍按独立技术故障和有限格式重试处理，不伪造反例。

第二步审查必须给计算题的每个 `required_outputs` 提供至少一个声明式反代检查：从金标取实际表达式，选择题设允许的参数，代回原始定义/方程，而不是另算一个正确答案后替换金标。记录题面原句、答案原句、参数合法依据、变量绑定、左右两式和比较关系。每个参数点的合法性条件先执行；点不合法只能说明检查无效，不能据此判金标错。

检查器用有理数和有理复数的精确运算，支持至多8×8矩阵、共轭/转置/伴随/逆、向量和模平方。没有浮点误差容差，也不执行模型生成的程序；仅解释有限的算术表达式白名单，限制长度、节点数、幂次和数值大小。除加减乘除与小整数幂外，不支持任意函数、导入、属性、文件、网络或系统调用。

例如原P03B金标，在 `r=2, κ=i/2, ω=1` 代入后：

- 输入功率检查：`norm2(S*vec([1,0])) = 21/5`，与无吸收要求的1不相等，程序确定失败。
- 暗态检查：把金标的 `d=(κ,-1)` 代回 `B*d` 得到非零向量，程序确定失败。
- 对照：`κ=1/2` 时，在同一r和ω下，金标公式的 `adjoint(S)*S=eye(2)` 精确成立。这只是一个合法点的对照，不证明全域正确。

| 检查层面 | 应检查内容 | 自动化边界 |
|---|---|---|
| 前提与唯一性 | 条件能否同时满足，是否漏定义、漏单位、缺边界/分支约定 | 独立推导和审查，不靠样本点证明唯一性 |
| 原式反代 | 金标代回题面定义/方程后残差是否为零 | 支持的有理/复数/矩阵表达式精确执行 |
| 参数合法性 | 正性、排除点、分母、参数区间；边界点只能按题设处理 | 执行声明的域条件，模型仍需核对翻译是否完整 |
| 物理约束 | 量纲、守恒、概率归一化、正定性、极限与对称性 | 可表达的代数恒等式程序执行，其他条件模型论证 |
| 输出覆盖 | 每个要求的输出均在金标中，且计算题有反代检查 | 按required_outputs逐项核对，报告未覆盖项 |
| 加/降难修改 | 改条件后原答案是否仍成立，是否扩大了非法参数域 | 每次版本修改重做全部前置检查 |
| 判分歧义 | 等价表达、倒数方向、分支编码是否被错判 | 后置争议复核，不私自篡改历史判分 |

模型文字结论为pass，但反代失败时，程序仍拒绝采样。表达式不支持、未覆盖计算输出或反代点不合法记 `unsupported`，阻止自动采样并要求补验证；这不等于题目已被证伪。纯证明/非计算题可明确标注无算术证书，报告保留未覆盖输出，不冒充已完成程序验证。

程序能确认“这组式子代入后是否成立”，题面/金标到这些式子的翻译和域条件的完整性仍由独立审查核对。原句锚点只验证来源存在，不自动证明语义一致；不能用模型编出的自证恒等式替代原题约束。有限点反代可以证伪，不能替代全域证明或学科专家复核。

## 逐题verifier的有限对抗

新实验开启[逐题verifier对抗生成](verifier-adversary.md)：带入题面、初始golden、完整推导和挖空步骤，用独立核定的合法/非法对照同时检查模型verifier与固定HLE判分。进入后这些输入冻结，最多修改两次verifier；对照不足只补对照。真实题面歧义、golden错误、HLE争议与未消除的不确定拒绝当前版本并记录上游问题，不能在此改题或触发外层作者重写。另建构造版本才可重做全部前置质检，不能通过放松检查保留当前版本。

## 状态、修复与可追溯性

- 质量失败按责任阶段处理：验算材料问题只修证书，前置科学缺陷返回作者；锁定golden错误则拒绝，不原地换答案。每次改题重新审查；进入verifier后冻结原题、金标与推导。修复用尽则 `rejected`，不把它当作过难题，也不把错误前提传给难度演化。
- 所有 `sample` 入口强制检查，通过后才允许付费GLM调用。每次降难、改条件/答案都使内容哈希变化，必须重新过关。
- 原始请求、实际模型名、三步审查结果、输入哈希、提示哈希、模型配置哈希和反代器代码哈希存入候选及请求收据。相同输入续跑可复用；修改提示、角色配置或反代器需重新验证。旧版本没有这道审查，不能直接作为新流程的已通过证据或导出。
- 接口失败保持待处理，不补写失败检查、不判为错误回答、不据此升/降难；请求预算、用量未知和失败费用沿用现有收据口径。
- 正确性阶段的JSON结构错误只允许有限格式重试；不重买独立解题结果，不重试已经合法返回的否定结论，也不把重试当作新题。
- 单独审查已有bundle：`diamond preflight work/submissions.jsonl --run-id correctness-only --mode pilot`。它执行综合复核及新增审查，完全不调用GLM或HLE答案判分；与完整QC使用不同run-id，便于成本分账。
- 报告新增 `consistency_passed` 与 `difficulty_measurement_valid`，旧采样原数值保留。导出必须验证当前内容的审查通过记录，并附审查依据。

当前仅降难规则：首4次全部正确直接拒绝；出现有效错答才补至16次。1–8/16进入后置复核与去重，9–16/16直接拒绝，0/16经正确性复核通过后才降难。前提都是题目和金标通过质量门槛，600秒解题截止按新口径计错，其他接口/判分/质检失败不当错答。
