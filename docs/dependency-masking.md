# 原始前提与完整依赖挖空

2026-10-27用户要求：先区分原始前提和可推导结论，再沿完整依赖链建立蓝图和挖空，核对实际题面剩余的推理。新入口为`configs/library-dependency-masking.toml`，显式启用`require_dependency_trace=true`；原论文硬步配置及历史冻结运行保持原身份。

## 锁定前

`ScientificGoal.premise_contract`将内容分成`primitives`与`derived`。前者逐项登记定义、模型规律、给定数据和影响答案的约定，记录来源定位及独立性理由；后者按拓扑顺序登记依赖ID、来源定位及从依赖恢复结论的论证。`exploration_ids`标记准备留给解题者发现的结论，`target_dependencies`连接最终目标；所有推导节点必须通向目标。不是按图节点数评难度。

目标的`assumptions`逐字对应原始输入。独立的`premise_boundary_audit`调用在选答案之前核查分类：论文中正确的结论不因此自动成为题面可给的前提。若明确发现推导结论被提升为已知、依赖缺失或等价提示，反馈至未锁定的目标选择；不能等金标锁定后再静默改模型。有限修订仍失败则记录该计划线未能构造。未能核实只记录具体限制，不恢复6Luna主观深度否决。

## 蓝图与题面

完整证明从原始输入经过全部推导节点到目标。`TaskDesign.dependency_trace.proof_links`把每个推导节点映射到完整推导的一基条目；`retained_primitive_ids`覆盖全部原始输入，`hidden_claim_ids`覆盖全部推导结论。现有`mask.proof_step_indices`必须覆盖这些证明条目的并集，允许隐藏多段连续或分支推理。引用可以支撑内部证明，但不能替代题面缺失的独立模型信息，也不能把被引结论改成给定条件。

题面生成只从登记的原始输入、锁定目标和必要约定取公开数据。完整证明及`additional_assumptions`里的推导事实是内部材料，不作为题面前提。待证明命题可以陈述；最终答案任务不能偷偷追加未经评测的证明义务。保持答案形式自由，保留标准背景和同等推理负担的合法解法。

## 实际剩余推理

前置审查新增两个独立调用：

1. `dependency_probe`只收到字面`question`，不见论文、目标依赖、金标、参考解、题目元数据或作者方法，输出实际用到的条件、最短解与剩余推理。
2. `dependency_question_audit`核验盲解并逐个映射全部推导节点，区分已作为前提给出、仍待推出、合法替代解不使用及未核实。检查独立前提是否充分、目标是否保留、证明链接是否忠实，并记录最短正确路线与仍需发现的内容。

把已登记的中间结论或等价解法提示作为可直接使用的前提给出，会阻断采样；遗漏独立前提、目标缩水或不实证明映射有具体见证时也阻断。正确短解、合法替代解和盲解失败本身不阻断；探针的错误不当作GLM答错。新检查不是形式化证明器，也不保证挖空后达到难度要求，最终仍按GLM首4次及必要时16次实测。

边界审查绑定目标、来源、提示及模型；实际题面审查绑定题面、金标、完整证明、依赖图、来源、提示、模型和合同代码。修改后不得复用旧通过资格；成功及失败请求通过原网关封印收据恢复，不重复购买相同请求。通用采样、正确性有效性及导出均检查依赖合同，关闭配置不能绕过已带合同的候选。嵌套记录使用现有JSON对象存储，不增加或自动迁移数据库schema。
