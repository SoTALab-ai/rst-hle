## 评估设置

- 解题请求 `glm-5.2`，有效响应实际模型为 `z-ai/glm-5.2`；temperature=1.0、top_p=0.95。
- Judge 为用户指定的 `gpt-6-luna medium`，有效响应实际模型为 `gpt-6-luna-2026-09-22`，沿用固定版本的官方 HLE 判分提示与字段。
- 无工具模式：仅题目与官方系统提示，不附搜索、浏览器、代码执行工具。
- 用户指定每次解题最多600秒，从取得并发槽开始，覆盖重试和等待；judge有独立的600秒期限。客户端没有发送 `max_tokens` 或 `max_completion_tokens`，本次记录中带客户端 token 上限的 solver 请求数为 0。
- 600秒客户端超时源于[官方示例代码](https://github.com/centerforaisafety/hle/blob/22ed3074b1e7b134bcbc09028d0ba320839b0655/hle_eval/run_model_predictions.py)；将它落实为含重试的硬限时，是用户随后明确选择的本项目协议，不能声称HLE全赛道统一硬限十分钟。
- HLE-Diamond另有[受控搜索与离线代码的工具模式](https://github.com/centerforaisafety/hle/blob/22ed3074b1e7b134bcbc09028d0ba320839b0655/docs/evaluation-with-tools.md)，本轮没有启用。

## 限时效果与服务限制

两份数学正确回答分别耗时约289秒、358秒，输出用量约69,952和75,044 tokens（含推理用量）。600秒能够容纳这两份回答；原先32k预算容纳不下。

取消客户端 token 上限后，仍观察到供应商在131,072输出 tokens处返回 `finish_reason=length`。这与本项目的600秒取消是两种不同的失败，均保留原始收据。本轮无返回usage的收据数为 5；费用不能据此记为零。费用按个人网关快照另存本地，未把上游 `usage.cost` 当作个人账单。

完整请求/响应、实际模型、样本编号、usage与失败收据保存在VM的PostgreSQL索引和产物库中。先前小批检查的同配置请求按原样本编号复用，未把同一回答冒充新的独立采样，复用阶段没有再次调用模型API。

本轮只校准参考题与限时行为，不能据此认定RST生成管线已达到2,000道交付目标。配置、复现方式和统计入口见[calibration.md](calibration.md)。
