# 顶刊理论材料 → 20题分阶段试产

这一轮按用户指定的方向，先选择理论材料，尝试从较难的种子向下校准。数学选取 Annals of Mathematics、JAMS、Inventiones 的5篇论文；物理选取 PRL、PRX 的5篇偏理论电磁学论文。每篇规划两个不同结论或推理结构，共20条出题谱系。期刊和理论筛选只是选材依据，实际难度仍由GLM5.2盲答决定。

论文清单见 [theory-pilot.catalog.jsonl](../configs/papers/theory-pilot.catalog.jsonl)，20条具体出题线见 [theory20.plan.json](../configs/papers/theory20.plan.json)。清单含固定arXiv版本、DOI、出版方链接、作者、分类、期刊元数据证据和理论筛选说明。理论标签是策展判断，不冒充期刊官方标签。源论文和预印本标题、首次在线日期与纸本期次日期可能不同，以链接及原元数据核对。

## 论文库与采集

在配置好的PostgreSQL上显式升级一次，然后按固定版本采集：

```bash
uv run diamond db-init
uv run diamond catalog-fetch configs/papers/theory-pilot.catalog.jsonl
uv run diamond papers --domain Physics --theory-only
uv run diamond papers --journal Annals --theory-only
```

`catalog-fetch`只从公开arXiv下载指定版本的PDF和可用的LaTeX源码；两次网络请求至少相隔3.1秒。源码作为文本读取，不运行TeX、论文代码或压缩包内文件，不把压缩包路径写入文件系统。读不到可用LaTeX时保留明确的PDF转录回退记录。已有同版本全文直接复用，不因新转录器改变顺序而覆盖旧材料。

元数据存入 `diamond.paper_catalog`，每次元数据修订写入 `paper_metadata_versions`。全文沿用 `sources` 的内容哈希和独立文件产物库。新增的SQL迁移是002，原001及已有请求/样本不改写。来源内容变化需要新的来源身份；期刊元数据可补充并保留版本史。

初始材料可通过期刊目录、DOI清单和arXiv查询发现，再核对出版记录并固定版本。当前可复现入口以已策展清单为边界，不把关键词命中或arXiv的自填期刊字段直接当作顶刊已发表证明。向后扩库应优先筛选：理论/方法文章、明确数学模型、可定位的推导或定理、完整可读取公式、可裁成有限且唯一答案的问题。预印本公开可读不等于允许重新公开分发全文；库保留许可字段，当前不重新托管源PDF。

## 生成和分阶段评测

```bash
uv run python scripts/run_question_experiment.py \
  --plan configs/papers/theory20.plan.json \
  --rates work/private/my-gateway-prices.json \
  --run-id theory20-first
```

价格快照使用真实网关的USD/百万tokens费率，包含 `observed_at`、`currency: "USD"`、`rmb_reference_exchange_rate` 和 `rates_per_million`。每个配置模型必须提供 `input`、`output`、`cache_read`、`cache_write` 四项；存在输入长度阶梯时提供 `input_tier_limit` 和 `above_limit`。不要把上游响应的 `usage.cost` 直接当成自己的网关账单。

每个版本先建立参考解，再出题，执行结构检查与分离调用复核。作者使用gpt-5.6-luna high；复核使用gpt-6-luna high；目标解题模型为GLM5.2；HLE官方模板的判分模型为gpt-6-luna medium。均不发送客户端输出token上限；每次调用最多600秒、包含接口重试。

1. 先测编号0–3。4次全部判对，记作“预筛后加难”，不声称取得16次难度验收。
2. 首4次有任何有效答错，复用这些回答，再测编号4–15；0/4同样要补到16次，避免过早认定太难。
3. 完整16次中，0次正确先复核错金标、歧义、缺条件和物理不可行性；通过后才降难。1–8次正确经再次复核与批次去重后记作 `screened`；9–16次正确进入加难。
4. 超时、截断、空作答、判分结构错误单列；样本不全不能成为可迭代父题。判分结构的有限修复固定原作答，不购买新的GLM回答。

每条谱系最多两次改写、最多保留一个版本。加难可隐去非必要提示、让参数可行域成为推导对象或组合约束；降难可给一个辅助引理、固定一个参数或减少一层耦合。两种方向都保留必要条件、正确性与唯一性，不能靠缺材料制造难度。来自同一论文的不同谱系仍执行材料/推理结构去重，换数字不能增加独立题数。

后续代码的后置复核会附带至多4份被判错的完整答案正文片段（每份最多12,000字符，明确标记截取）及原判分理由，检查所谓错答是否其实符合题面。比值方向、分支编码若只写在金标中，或者无吸收模型的参数域违反能量守恒，都必须退回。复核拒绝会阻止留存与演化，不会悄悄修改旧判分。新生成提示也改为优先一个紧凑目标，避免靠增加大量容易漏报的子问制造低通过率。这些改进不追溯替换 `046b0c9` 试产快照；其补充反例检查单列，保留原统计。

后续配置将全局并发上限设为16、解题并发上限设为14，为判分及复核留出容量；排队时间不计入尚未发起的HTTP请求时限。未配置 `solver_concurrency` 时保持原有共享队列行为。冻结的首次试产使用原共享16并发，未在运行中调整。

## 统计与费用口径

- 首轮留存率：第0轮最终进入 `screened` 的独立谱系数 / 全部20条计划谱系。作者失败、质量拒绝和接口失败都留在分母。
- 有限迭代留存率：至多两次改写后拥有合格版本的谱系数 / 20。另列各版本、初筛全对、完整0/16、完整9–16/16及异常数量。
- 记录加难、降难的父子变更；同一谱系的多个版本不重复计算独立成功。作者内部修复会增加请求和费用，不增加谱系数。
- 费用合并生成、复核、盲答、判分、去重、失败和重试；按HTTP收据去重，计入截断响应的已返回用量，未返回/取消用量保持未知。报告每条计划谱系和每条最终留存谱系的已知API成本；零留存时单位成功成本为空。
- 默认20条谱系最多60个评测版本；已返回用量的软阈值为90美元，另有2200次HTTP请求上限。在途请求、取消及未知用量会影响最终账单，这个阈值不是账单硬上限。运行快照独立于主库和后续代码修改。

输出位于 `work/runs/RUN/experiment-report.json` 与 `candidates.json`，保留完整题面、参考解、谱系和每次判分。`pilot` 的采购交付数始终为0。报告是这批策展材料上的机器质检留存率，不是整个HLE题库的通过率，也不是人工确认的科学真值率。首4次决定后续选样，因此不能拿补测子集估计无条件模型准确率。同论文题目存在相关性，未校正聚类的区间只作描述，不能当作总体置信区间。
