# 来源路由、断点续跑和失败恢复

## 完整试跑入口

```bash
uv run diamond crawl --ids 1706.03762v7 --limit 1
uv run diamond route-sources --run-id route-first
uv run diamond run --run-id evolve-first --mode pilot
```

`configs/pilot.toml` 与 `production.toml` 的 `source_routes_path` 指向 `work/source-routes.json`。路由根据已导入全文、固定v3分类生成，每个来源最多支持五个子类，也允许返回空列表。它是模型筛选，不是学科正确性的证明；后续静态检查与独立复核仍必须通过。路由记录来源全文哈希与分类表哈希，来源或分类改变后拒绝使用旧映射。自动生成只处理被来源支持的子类；没有映射时要求先路由，或用 `--subtopic` 明确指定人工试跑目标。

`uv run python scripts/run_pipeline_pilot.py --run-id YOUR_RUN` 将路由、解答先行生成、题面生成、复核、16次盲答和判分串联执行。`outputs/YOUR_RUN.bundles.json` 是可检查的试跑候选，包含拒绝原因、参考解与证据；`delivery_items` 固定为0，不是采购交付包。

## 中断后的行为

- 每得到一组 solver/judge 结果，立即保存候选与样本。恢复时只处理缺失编号，已完成15次时不会重新购买这15次回答。
- 已有16份判分但去重阶段中断的候选，恢复后继续去重和最终门槛检查，不因“已有16次”而跳过。
- run-id 绑定调用入口、提交清单、配置、来源、提示与代码。更换题目或从QC切换到生成，必须使用新run-id。
- 单题超时、截断或判分格式错误留下部分样本，阻止该题验收；批次继续处理其他题。缺少样本的题不会成为演化父题。
- 认证错误、模型路由错误、请求预算耗尽、存储故障或缓存损坏会中止批次，取消并等待其他在途任务，防止后台继续无目的调用。预算耗尽与普通中断分开记录。
- `completed_with_errors` 表示批次已结束、仍有候选样本不全；不是全部题通过验收。

## 请求与费用留痕

每次HTTP尝试都有独立编号、本地原子收据和可恢复的用量记录。持久化完整模型响应后，再登记数据库的attempt索引；HTTP错误体和认证头不进入日志。失败响应有统一错误分类，不暴露原始错误正文。

完整响应先写带完整性哈希的本地恢复日志，再提交PostgreSQL对象索引。数据库写入失败后，恢复时核对请求、参数、样本盐值与完整性哈希，先补回数据库记录，再继续使用原响应；不会直接绕过数据库，也不会默默重新付费。attempt登记幂等；读到损坏日志则停止，要求恢复原件。

缓存键包含输出协议、实际请求参数、端点哈希、样本盐值和时限。同一个网关实例并发请求同一个逻辑样本时只实际购买一次。不同采样编号始终独立。复用请求的attempt归属于原始调用的run-id，不会虚增新运行的HTTP次数或账单。接口仍可能在取消后收费，未返回usage的尝试保持未知，不能记为零费用。

新版改变了请求缓存和指纹格式，旧版运行保留为历史记录；不得用新代码伪装无变更地续跑旧版run-id。

## 来源与导出

论文先下载到临时文件，检查体积、PDF类型与解析完整性，再原子替换。中断、网页错误响应和损坏PDF不会覆盖已有缓存。

导出重新检查判分完整性、质量门槛、谱系独立性、材料唯一性和子类配额。manifest只包含实际导出候选的运行，防止把同数据库中的参考HLE标签或其他运行内容一起带出。

## 验证范围

新增故障注入测试覆盖：数据库索引/attempt登记失败后的付费响应恢复、重复逻辑请求去重、坏缓存拒绝重发、接口错误脱敏、跨题样本复用拒绝、取消任务清理、逐样本恢复、去重中断恢复、单题错误隔离、提交清单变化拒绝、来源路由过期与未知分类、论文下载失败、完整路由→生成→质检→导出的控制流程。数据库测试使用独立 `_test` 库，含实际PostgreSQL读写。

确定性测试中的模型回复是测试替身，验证控制逻辑和业务门槛，不证明真实题目的学科真值或生成良率。真实API试跑另行记录，不能用测试替身冒充。
