# 逐题verifier的对抗生成

这道门槛在GLM难度评测之前。输入包括实际题面、锁定来源结果、golden、完整逐步推导和最难步骤的挖空设计。golden是待反驳的提案，不是审查公理。盲推导与GLM仍只看题面。

流程：完整证明经复核形成题面 → 原有综合/盲推导/自洽/公式翻译/精确反代 → 生成逐题verifier → 构造合法对照与错误变体 → 独立核定对照 → 分别运行verifier与固定HLE判分 → 独立检查三者一致性 → 最多两次修改 → 通过后才测难度。

2026-10-25用户最新边界：`freeze_question_at_verifier=true`默认开启。只有全部前置检查通过才能进入verifier；进入后冻结题面、golden和完整推导。verifier内部不能修题，外层作者也不能在verifier失败后重写整包。真实上游缺陷拒绝当前版本、返回具体原因，另建版本才可重新构造并重过前置检查。下面的动作表以此新协议为准。

verifier逐项列出题面要求的输出、原句锚点、接纳规则与等价表达。所需条件分为题面明确给出、能从保留信息推出、题面要求求出。隐藏推理本身可以继续隐藏；不能把参考证明里的额外前提当成题设。不得添加题面未要求的最优性、归一化、证明格式或物理参数限制。

每轮至少包含两个合法等价答案、两个错误近邻，并对每个要求的输出给出一个经独立核定确属错误的反例。挑战者的标签不直接当真值：另一调用只看题面、候选答案、完整证明与来源，不看verifier或挑战标签。随后实际执行模型verifier和HLE判分，再独立核对条件与输出覆盖。程序还检查控制覆盖、ID映射、误杀、漏检和不确定状态；模型声称pass不能绕过这些检查。执行的是固定受限算术检查器和模型调用，不执行模型生成的代码。

2026-10-27用户明确删除“金标文本本身必须完成证明”的检查。金标保留为参考材料，科学结果结合完整推导与来源核对，不再作为一份答卷加入oracle、verifier或HLE对照。`golden_valid`只核科学结果，不因金标文字省略可推导步骤而失败。真实答卷中的必要论证仍按实际题意检查；原题面、金标、完整推导和旧冻结记录不因此改写。

| 发现 | 动作 |
|---|---|
| 合法等价答案被verifier误杀 | 修verifier，保留题面和golden |
| verifier漏检，题面本来明确 | 补verifier漏掉的检查，不改数学目标 |
| 漏检暴露题面歧义/必要信息不足 | 拒绝当前版本并返回上游；本阶段不能改题或放宽verifier |
| golden错误或仍不确定 | 退回，不通过替换答案或放宽verifier解决 |
| HLE与独立核定冲突 | 单列判分争议；局部verifier不能静默覆盖HLE判分 |
| 两次修改后仍不一致 | 拒绝；不进入难度采样 |

初版加最多两个verifier修正版，合计至多三轮，所有版本绑定同一题面哈希与证明上下文。题面原句锚点和输出名称不符合逐字合同时，另外允许有限格式修复，不改变验收数学含义。锚点修复只返回定位字段，接纳规则、条件和等价形式保持，仍需完整对抗。每版保存原spec哈希、定位修改、请求ID和结果。旧可改题协议仅在明确历史回放时使用`freeze_question_at_verifier=false`，不覆盖旧冻结统计。已有样本永远不能清空后原地改题。

当题目/golden检查均通过但合法或非法对照数量不足时，按`consistency_schema_repairs`有限追加对照（默认1次）。旧案例逐字、逐项、按序保留，旧oracle判定也不得翻转以补数量；追加后全部案例均由verifier和固定HLE执行。套件与原HTTP费用全部存档。补对照不能把科学不确定、错误golden或HLE冲突变成通过，覆盖仍不够则阻断。

独立质量副本的真实诊断入口为 `scripts/check_verifier_adversary.py`；运行网关在缓存和网络之前拒绝solver角色，诊断不产生难度样本或交付量。

原句定位先做受限排版投影。仅verifier定位额外容忍英文冠词首字母及`is a/be a`语法差异；返回题面中唯一、连续的原文片段，不改条件、接纳规则、输出或golden。原模型响应、原spec哈希、修改前后锚点与位置一并保存，恢复时重新验证这些收据。来源引文不允许这些语法改写。无法定位仍做有限格式修复；定位成功也必须完成全部独立对抗，不能直接标成通过。

题目目标和答案形式按已锁定的科学目标保持，不预设短答案。不得把金标印进题面代替解题负担。金标说明可以省略已由完整参考推导支持的步骤；真实答卷仍须完成题面明确要求的论证，独立oracle不能替答卷补写未给出的必要论证或参数域推广。固定HLE模板保持原样。

`scripts/replay_rejections.py`是另一条**零模型调用**的阶段回放入口：验证完整证据清单和原HTTP响应封印，只重算确定性的入口/锚点合同并核对已有答卷。缺失的模型审查保持待完成，报告不计新增科学通过或难度通过，不能当成整个实验重跑。

开启配置：`configs/theory10-verifier-adversary.toml`，其中 `require_verifier_adversary=true`、`verifier_max_revisions=2`。旧运行配置保留历史协议，不热修改正在运行的快照。`sample`、完整QC与导出均检查此合同；内容、提示、模型或协议变化使旧对抗记录不能直接复用。

单题真实VM诊断的全过程、失败与成本见[2026-10-24结果](validation/verifier-probe-2026-10-24.md)。

当前逐题verifier是前置质量审查合同，不替代最终HLE答案匹配。对抗中的HLE控制使用相同的冻结user模板和已版本化的system抽取指引。通过有限对抗或反代不能证明全域正确性；独立调用默认仍使用同一6-luna模型，可能存在相关漏检。
