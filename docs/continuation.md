# 首20份按新协议续产

PR #10已按用户授权合入其目标分支`codex/library20-reader-cap`，合入提交`64436ba9b6959f0b3caa959e4468b9c34727842c`。续产沿用首20份数学/理论物理材料，读取器继续停在50份，不重新下载、解析或购买旧规划。

入口为`scripts/continue_library_question_campaign.py`。在新个人PG库和冻结源码/提示/配置中执行；原证据包括20份PDF、原规划、候选及原HTTP响应，验证完整清单和请求封印后只读导入。原试产库不允许作为续产目的库。

## 复用范围

| 原产物 | 续产处理 |
|---|---|
| 20份论文正文/补充的冻结转录与PDF | 验证原件与哈希后复用，不重新解析 |
| 20份作者规划、9份已有独立性审查 | 提案不变且绑定原收据时复用；之前缺审查的多题材料补独立审查 |
| 3道首4次全对的题及12份答卷/判分 | 保留原“过易拒绝”终态，不加难、不重新购买GLM |
| 未完成题的已有金标、完整推导、题面 | 在新run作为待审种子；重新做受新协议影响的独立审查，不复制旧通过资格 |
| 已有verifier草稿 | 只在原题面/推导完全一致时复用并修定位；仍做完整新对抗 |
| 新修复题或未测题 | 正确性通过后才补必要样本；4/4拒绝，否则补16次，过难才降难 |

原规划共50条提案，3条已有过易终态；其余至多47条进入本轮，尚需多题独立性筛选。25条旧受理线均能找到提案收据，20条已有完整推导（含3条已关闭线），9条已有题面（含3条已关闭线）。实际新受理数以补审结果为准，不用计划数充当成功题数。

种子保留原候选ID、请求ID、此前作者修复次数及内容哈希。原完整推导先由当前独立审查复核；修复调用返回完整版本，金标/目标不静默更换。来源对齐用`advisory`，错误金标、证明缺口、条件不全、判分争议仍阻止难度采样。

另有解题保护：同题同样本的旧完成答卷优先返回原响应ID，核对模型、完整payload、端点/时限协议和封印；兼容性不明则拒绝重购。若题面或golden的判分上下文改变，旧GLM答卷仍可复用，而judge可重新审查。复用记录说明新请求盐与原收据的关系，不伪造新HTTP；样本原支付run保持。

## 逐题补测调度

新代码将作者/质检与评测分为两个受控任务池。首4次存在有效错答或solver deadline时，该题立即补缺失的12次，与其他题的出题、质检和首测并行；4/4直接拒绝。默认作者并行4题、评测并行2题，底层全局及solver并发限制继续生效。并行完成后的去重仍串行，不增加重复留存。

此变更需要新冻结代码与run，不覆盖正在运行的`25f83b9`快照。该旧快照仍采用整代首轮完成后补测；2026-10-25全部47条首轮处置结束后，物理2/4题已按原管线开始补测。已有GLM答案和支付归属保持，不为启用新调度重新购买答案。恢复、接口失败隔离和后审失败不得降难的验证见[逐题补测验证](validation/streaming-evaluation-2026-10-25.md)。
